## Concept

This endpoint allows you to reply to an option list, simulating a user tap on one of the options previously sent via [send-option-list](/message/send-option-list).

<Info>
The list must have been previously sent or received. The **option ID** must match the `id` defined for that option when the list was sent or in the received webhook.
</Info>

## Attributes

<InstanceId />
<Token />

### Required

<ParamField body="phone" type="string" required>
  Phone number (or group ID) in the format COUNTRY CODE + AREA CODE + NUMBER. Example: 551199999999
</ParamField>

<ParamField body="messageId" type="string" required>
  ID of the option list message being replied to.
</ParamField>

<ParamField body="responseOptionId" type="string" required>
  ID of the selected option. It must be the same `id` defined in the list when it was sent.
</ParamField>

---

## Request Body

```json
{
  "phone": "5511999999999",
  "messageId": "3EB0C767D82B0A6E9F5F",
  "responseOptionId": "1"
}
```

### 400

Make sure the request body is present and the required fields (`phone`, `messageId` and `responseOptionId`) are filled in.

### 405

Make sure you are using the correct HTTP method (POST).

### 415

Make sure to include the Content-Type: application/json header.
